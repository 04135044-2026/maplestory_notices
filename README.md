# 新楓之谷公告懶人包

在本機查閱台灣《新楓之谷》官方活動公告、搜尋獎勵取得方式，並把重要期限匯出到日曆。網站使用 Node.js 24，將公告 HTML 保存為來源快照；資料可存於本機 JSON 或 PostgreSQL。

## 第一次使用

1. 安裝 Node.js 24，依下方指令安裝並啟動網站。
2. 若要使用自動分析或 AI 問答，先選「公告管理 → 設定 AI 模型與更新摘要」，設定 Gemini、Codex CLI 或本機 Ollama 並測試。模型可能需要金鑰、登入或額外安裝。
3. 選「公告管理 → 匯入與查找官方公告」，貼上官方版本公告網址。新安裝沒有既有公告或資料，也可以先匯入公告，之後再設定模型。
4. 回首頁用名稱搜尋活動或獎勵，點結果查看取得方式和官方來源；也可使用日曆、關注和備份功能。

匯入版本公告後會排入自動分析；模型未設定或分析失敗時，仍可查看已保存原文，並在公告管理檢查狀態。AI 摘要可能有誤，請以官方原文為準。

## 專案架構與使用技術

```text
瀏覽器
  └─ Node.js HTTP 網站（src/site.mjs）
      ├─ 官方公告擷取、拆分、活動及日曆（Cheerio）
      ├─ 模型摘要與問答（Gemini / Codex CLI / Ollama）
      ├─ 語意搜尋（Ollama embeddinggemma → PostgreSQL pgvector → 活動筆記與獎勵取得方法）
      └─ 儲存（本機 JSON 或 PostgreSQL；pg 套件）
```

網站以原生 Node.js HTTP 與伺服器產生的 HTML/CSS 建立；測試使用 Node.js 內建測試工具。語意搜尋從已收錄的活動與獎勵找出可參加或仍可領獎的項目。向量預設使用本機 Ollama 的 `embeddinggemma`，可用 `MAPLE_EMBEDDING_MODEL` 指定；生成摘要與回答的模型另外在網站設定。

## 安裝與啟動

```powershell
npm ci
node --env-file-if-exists=.env src/start.mjs
```

啟動後開啟終端顯示的網址，預設為 [http://127.0.0.1:3181](http://127.0.0.1:3181)。可用環境變數 `PORT` 指定連接埠。到「公告管理 → 設定 AI 模型與更新摘要」可選 Gemini、已登入的 Codex CLI 或本機 Ollama。填寫模型後，先按「測試所選模型」，成功再按「保存長期預設」。Gemini 金鑰留白會沿用 Windows 本機加密儲存中既有的金鑰。啟動時會移轉舊版金鑰檔及專案 `.env` 裡的 Gemini 金鑰，並從原檔清除該值。Ollama 需在本機執行並已安裝該模型。

第一次使用可從「公告管理 → 匯入與查找官方公告」貼上官方版本公告網址並保存來源。收錄後可搜尋「核心寶石」，點「查看取得方式」，從活動筆記核對資格、步驟、上限和期限。已保存的結果可離線查閱。

## 首頁與活動筆記

- **活動一覽**預設顯示進行中或仍可領獎的主活動。桌面每排兩張卡，手機改為單欄。卡片顯示子活動數量，展開後可點名稱直達活動筆記。
- **近期截止**以主活動名稱顯示。同一主活動下，截止時間和種類相同的子活動合併一列，可展開查看。參加截止、領獎截止、效果到期及已知的補完截止依各自期限顯示。日期採 `MM/DD HH:mm`，僅知日期時顯示 `MM/DD`。
- **全部活動**依主活動分區，包含已結束的活動。首頁可依名稱、狀態、獎勵類型或關注項目查找。搜尋獎勵名稱時，先看官方領獎期間。公告只列活動期間，且沒有另訂開領或延後發放時，活動期間內的結果會標示「依活動期間顯示」。可以搜尋獎勵分類，例如「椅子」也會找到公告明稱為椅子、但名稱不含「椅子」的獎勵。活動名稱與方法名稱搜尋同樣排除不可領取的項目；歷史活動仍可從「查看全部已收錄活動」查閱。
- **外觀**可選跟隨系統、淺色或深色，瀏覽器會記住選擇。日曆色條有清楚的邊線與文字標籤。

公告明列子活動專屬的領獎期間、效果到期或限時補完規則時，會在對應項目標示。像「12/02 維護後」會保留原文和日期，確切時刻維持未知。

## Windows 原生 PostgreSQL 與 pgAdmin

已切換到 Windows 原生資料庫後，在專案資料夾開啟 PowerShell，執行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-native.ps1
```

輸入 `maple_app` 的 PostgreSQL 密碼，看到 `http://127.0.0.1:3211` 後再開啟網站。腳本使用原生資料庫 `127.0.0.1:5433/maple_native` 和既有的 `maple-trial-01` 資料集。執行原則參數只套用到這次啟動的 PowerShell 程序。要停止網站，在該視窗按 `Ctrl+C`。

1. 使用 [PostgreSQL Windows 安裝程式](https://www.postgresql.org/download/windows/)，選擇 PostgreSQL 18、pgAdmin 4 與命令列工具。若原 Docker 資料庫使用 `5432`，將原生服務設為 `5433`。自行設定管理員密碼，安裝完成後可在 Windows「服務」查看及啟停 PostgreSQL。
2. 依 [pgvector Windows 安裝說明](https://github.com/pgvector/pgvector#windows) 使用 Visual Studio 的 C++ 工具編譯並安裝相同主版本的擴充套件。用 pgAdmin 連線 `127.0.0.1:5433`，建立專案登入角色及由該角色擁有的資料庫。以資料庫管理員在該資料庫執行 `CREATE EXTENSION IF NOT EXISTS vector;`，再用 `SELECT extversion FROM pg_extension WHERE extname = 'vector';` 確認已啟用。
3. 在舊站「備份與還原」下載 JSON 備份。另開 PowerShell，設定 `MAPLE_DATABASE_URL` 指向新資料庫、`MAPLE_DATABASE_NAMESPACE` 為 `maple-trial-01`，並以 `PORT=3212` 啟動試用站。從試用站「備份與還原」上傳 JSON；核對公告原文、活動筆記、關注、人工修正和圖片獎勵。語意搜尋另用一個沒有關鍵字命中的口語句確認 Ollama 和 pgvector 都能回應。
4. 驗收後，暫停舊站的排程、匯入與資料修改，等處理中的工作結束。舊站仍運行時下載最後一份備份，再關閉舊站並把備份還原至試用站。結束試用站，沿用同一組資料庫連線及資料集設定，在 `3211` 啟動網站。停止 Docker 中的舊資料庫，再確認原資料及語意搜尋可用。
5. 若需回復，先匯出切換後的資料，再關閉原生資料庫版網站以釋放 `3211`。從 Docker Desktop 啟動原資料庫，再用原連線及資料集設定啟動 `3211`。日常可用 pgAdmin 查看資料庫，或在資料庫的右鍵選單選「Backup」。跨環境移轉使用網站匯出的 JSON。

PowerShell 可在已設定資料庫連線的同一個視窗中執行以下指令啟動試用站。
連線格式為 `postgresql://使用者:密碼@127.0.0.1:5433/資料庫`，帳密中的特殊字元需做 URL 編碼。將連線資料保存在本機環境設定。

```powershell
$env:PORT = '3212'
$env:MAPLE_DATABASE_NAMESPACE = 'maple-trial-01'
$env:MAPLE_ENABLE_SCHEDULE = '0'
node --env-file-if-exists=.env src/start.mjs
```

## 用 Docker PostgreSQL 試移轉一份備份

PostgreSQL 可以直接安裝在 Windows，無須 Docker；也可以使用 Docker 或連線到現有的 PostgreSQL 伺服器。無論使用哪種方式，資料庫服務都需要運行，並在 `MAPLE_DATABASE_URL` 設定連線網址。語意搜尋還需要資料庫安裝 pgvector，以及本機 Ollama 和向量模型。更換資料庫前，請先從網站下載備份，再依下方步驟試移轉，不會自動搬移既有資料。以下是使用 Docker 的範例。

先在原本的網站開啟「備份與還原」並下載 JSON。保持 Docker 的資料庫運行。另開 PowerShell，在專案資料夾執行以下指令。若 Docker 使用 5433，將 5432 改成 5433。

```powershell
$mapleSecretFile = Join-Path $env:LOCALAPPDATA 'maple-postgres/.env'
$maplePassword = ((Get-Content -LiteralPath $mapleSecretFile | Where-Object { $_ -like 'MAPLE_DB_PASSWORD=*' }) -split '=', 2)[1]
$env:MAPLE_DATABASE_URL = 'postgresql://maple_admin:' + [uri]::EscapeDataString($maplePassword) + '@127.0.0.1:5432/maple_dev'
$env:MAPLE_DATABASE_NAMESPACE = 'maple-trial-01'
node src/import-postgres.mjs 'C:/請改成實際路徑/maplestory-backup.json'
```

看到「試移轉完成」後，在同一個 PowerShell 啟動試用網站：

```powershell
$env:PORT = '3211'
node --env-file-if-exists=.env src/start.mjs
```

開啟 `http://127.0.0.1:3211`，搜尋既有備份中的獎勵，確認活動筆記、取得方法及官方原文能開啟。按 Ctrl+C 後重啟，再核對一次。試移轉模式預設暫停每日排程，避免和原網站重複抓取。確認只由試用網站執行排程後，可在啟動前設 `$env:MAPLE_ENABLE_SCHEDULE = '1'`。同一份備份在內容未變更時可直接重跑；不同資料請另用資料集名稱。PostgreSQL 模式可從「備份與還原」下載及還原備份，還原會建立並切換到新的資料版本，上一個版本可以用「下載還原前的備份」取回。

## 回歸測試

```powershell
node --test
```

測試使用本機 HTTP、替代公告來源、模擬模型回應及固定時間，驗證匯入、活動期間、搜尋、日曆匯出與備份還原等流程。公告快照、整理結果及可取得的模型用量存在本機 `data/`。Git 排除 `data/` 與 `.env`。

## 公告拆分與核對

程式根據正文容器、標題、分隔線、日期及資格判斷活動和子活動的歸屬，並保留原文、表格與圖片的位置。共用條件按適用範圍引用，子活動獨立的日期及資格優先。

在「匯入與查找官方公告」點入已保存的公告，再選「在網站查看官方公告原文」，可依順序查看段落、表格與圖片，或下載完整來源快照。歸屬不明時可在拆分核對頁檢視原文，選擇活動、取得方式及適用段落。頁面若顯示「用 Agent 分析待確認的歸屬」，可取得附原文段落編號的建議，再人工確認並保存。

活動筆記顯示已整理的摘要和選入的官方圖片。要補做摘要，從「管理筆記」展開「摘要整理」，再按「用預設模型整理這個方法」。模型收到指定方法及適用的共用段落，摘要中的來源可回查原文。

## 玩家 Agent 查詢

1. **詢問 Agent**。讀完活動筆記後，可在下方直接提問。送出會使用已設定的 AI 模型，可能產生費用。回答顯示在活動筆記內，點選依據可核對原文或表格。

   長公告會先從這個活動找相關的原文、表格列與已核對圖片文字。關鍵字不足時會用本機向量搜尋補找。向量搜尋暫時不可用時，仍可根據查到的文字回答，缺少依據的條件會標為待確認。
2. **比較兩種取得方式**。從同一區點「比較兩種取得方式」，選「燃燒之城應援」與「墮落雷霆應援」，查看並排的資格、方式、獎勵、限制與成本。也可選不同活動的方法。
3. **口語搜尋活動與獎勵**。首頁輸入「活動椅子有哪些」後按「語意搜尋」。系統會先篩出目前可取得的椅子，再依查詢排序；點結果可查看活動筆記或取得方法。例行及商城公告不列入。這需要 PostgreSQL、pgvector、本機 Ollama 及向量模型。名稱搜尋結果較少或較多時，也可按「用 Agent 搜尋」查詢已收錄的活動及取得方式。

活動問答、比較及 Agent 搜尋會使用「公告管理 → 設定 AI 模型與更新摘要」設定的生成模型（Gemini、已登入的 Codex CLI 或本機 Ollama）。語意搜尋則使用本機 Ollama 向量模型；兩者設定不同。公告筆記、表格及名稱搜尋可直接查閱。

從活動筆記開啟「管理筆記」，在「官方圖片來源與選圖」可預覽原圖並選入懶人包。官方圖片有文字或數值時，也可手動核對或用 AI 產生辨識稿，再按「核對並加入活動筆記」。「詢問 Agent」可以引用已核對的圖片文字。圖片換版後需重新核對。

## 回溯官方公告

在上方「公告管理」分頁點「匯入與查找官方公告」，再按「檢查官方公告列表」。網站以台北日期回溯最近 90 天，顯示已保存來源、待確認版型及擷取失敗的項目。較舊的官方公告可從同頁貼網址補入。

待確認的版本公告可以先讀原文及表格，再指定活動名稱、取得方法和適用段落。確認後可從首頁搜尋該活動，並在活動筆記手動整理摘要。例行公告和已收錄活動的相關異動會附來源供核對。

「查看追蹤中的公告」列出各來源的追蹤原因，並提供手動重查。「設定每日自動更新」預設台北時間 14:10，程式運行且電腦清醒時會自動更新，恢復後可補查最近一次錯過的排程。PostgreSQL 模式預設停用排程，需設定 `MAPLE_ENABLE_SCHEDULE=1` 才會啟用。「查看處理進度與重試」可繼續待處理來源或單獨重試失敗項目。

## 活動日曆與備份

在「活動日曆」點選日期可查看當日開始、截止、開領、領獎截止、效果到期與補完項目。已辨識的時間點可匯出為 `.ics`，並可另選有官方時刻的每日或每週重置提醒。時刻未知的日期以全天事件匯出。活動日期或提醒規則變更後，網站會提示重新匯出，舊事件可在外部日曆管理。

「備份與還原」可下載本機資料的 JSON 備份，也可選檔後確認還原。還原會校驗檔案，將網站切換到該備份的資料版本，原本資料目錄留存。備份包含已保存的來源、圖片、摘要、人工拆分、個人修正、關注、問題來源、日曆匯出紀錄、排程與模型途徑。請在另一環境重新設定 API 金鑰或登入 Codex。
