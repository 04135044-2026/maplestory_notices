# 新楓之谷公告懶人包

工單 01 的本機版本。使用 Node.js 24 的 HTTP 伺服器、原生 HTML 和本機 JSON 保存結果。公告 HTML 另存為來源快照。這個版本的匯入和搜尋涵蓋公告 19129 的粉絲俱樂部與燃燒之城應援。

在工作區的 `.env` 設定免費 Gemini 專案的 `GEMINI_API_KEY` 和 `GEMINI_MODEL`，可參考 `.env.example`。啟動後開啟終端顯示的網址，預設為 http://127.0.0.1:3181。

```powershell
node --env-file-if-exists=.env src/start.mjs
```

首次啟動時，在首頁展開「公告管理」，選「匯入並整理公告 19129」。匯入成功後搜尋「核心寶石」，開啟「查看取得方式」。可從活動筆記核對資格、步驟、上限及期限，再點「查看官方公告」比對原文。已保存的結果可在離線或重啟後查閱。

```powershell
node --test
```

測試透過本機 HTTP 操作網站，以替代的公告來源、模型回應和時間驗證匯入、搜尋、重開及模型輸出無效時保留舊結果。真實匯入則使用已設定的 Gemini 模型。取用的公告快照、模型及可取得的用量記錄在本機 `data/`，憑證和這些資料皆由 Git 排除。

## 公告 19129 的多活動拆分

首次執行前以 `npm ci` 安裝 HTML 解析套件。首頁的「查看公告 19129 的全部活動」讀取已保存快照，可直接查閱，無須重新匯入。活動頁顯示適用資格、期間、步驟、重要限制及段落依據。需要模型整理時，展開該方法的「Gemini 整理」並按下按鈕。

`beanfun-eventad-19129-hierarchy-v1` 只支援已核對的 19129 正文容器。程式以分隔線及已驗證的粗體標題樣式尋找候選邊界。明列參加日期和資格的區塊是獨立活動。只有圖片的群組標題用來分組。活動內的 15pt 標題代表方法，沒有獨立資格與日期的 20pt 說明歸為補充。表格依列及儲存格順序保存。

活動身分優先使用活動自身的圖片網址集合，無圖片時用自身正文。方法也從所屬活動與自身來源建立識別，因此只改標題或移動整個區塊時仍可追蹤。來源內容和圖片都變更的身分合併仍需另行確認。共用期間、注意事項、適用補充及圖片網址保存在 `data/activity-catalog.json`。未知版型保留原快照並顯示拆分待確認。圖片在本票保存網址與範圍，圖片內容辨識另行驗證。

Gemini 只收到指定方法和適用共用段落。結果與可取得用量存在 `data/activity-methods.json`，每個欄位的來源須屬於該方法的輸入。網站仍可直接查看來源表格與段落。
