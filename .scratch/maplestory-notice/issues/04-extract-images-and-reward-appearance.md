# 04: 整理圖片表格並呈現官方獎勵外觀

**What to build:** 依已確認區塊辨識公告圖片／表格，呈現官方外觀；圖片內多活動或歸屬不明時可人工確認。

**Blocked by:** 03：檢視並調整待確認的活動拆分

**Status:** ready-for-agent

**Completion:** pending

**Specification:** [正式規格 v1.2](../../../SPEC.md)；US-006、US-007、US-015、US-036；D2、D5、D7、D14；AC04、AC05、AC08、AC18、AC27、AC28。 補充 AC33；D15。

**Decision:** 遵循 SPEC.md D14：程式依已驗證模板／人工確認拆分；LLM 僅處理指定內容的提取、圖片辨識與摘要。

## Acceptance criteria

- [ ] 用 19129 的椅子及幸運箱驗證圖文／表格對應，活動商店沿用規格的原圖規則，選入圖片不觸發辨識。

- [ ] 完成真實 Gemini 圖片輸入與網頁獎勵展示，不以外部補圖或生成圖替代。
- [ ] 外觀只在能確認對應時標為該物品；多物品共圖保留整張及待確認提示。
- [ ] 單張圖片失敗不抹除其他成功資訊，原圖與辨識內容保持關聯，已保存圖片離線可查。
- [ ] 圖片辨識供內容核對；活動邊界由已驗證規則或人工確認後才執行摘要，LLM不默默重組。
- [ ] 保留原圖與共用條件、區塊關係，選取必要圖片供模型處理。

- [ ] 經網站操作或實際輸出驗證上述交付行為；依已確認的整體入口，以保存來源、可替換模型回應及時間建立適用的可重複驗證。既有相關驗證仍通過。

## Scope and verification

本任務引用的故事與驗收條件可能由多張任務共同完成；本張負責範圍以上述交付行為及核取項目為準，不將其他任務尚未完成的功能當成本張完成證據。

完成時記錄使用的來源案例、實際操作／驗證結果及尚存限制。涉及真實模型呼叫時，記錄可取得用量；未知量明示未知。前置任務未完成時保持等待，不以 ready-for-agent 標記取代依賴檢查。
