# 09: 合併多來源與顯示官方更正差異

**What to build:** 版本公告與例行摘要在明確相關時共同支援活動，官方更正優先並顯示差異，保留矛盾。

**Blocked by:** 05：區分活動期限與顯示活動狀態；07：區塊更新與共用條件影響追蹤

**Status:** ready-for-agent

**Completion:** ready for player acceptance

**Specification:** [正式規格 v1.2](../../../SPEC.md)；US-016、US-017、US-018；D1、D3、D4、D8、D14；AC06、AC07。 補充 AC33、AC34；D15。

**Decision:** 遵循 SPEC.md D14：程式依已驗證模板／人工確認拆分；LLM 僅處理指定內容的提取、圖片辨識與摘要。

## Acceptance criteria

- [ ] 期限旁顯示與該欄位有關的差異及查證入口；逐段比對和來源關聯操作在公告管理能定位同一活動。

- [ ] 明確延期可更新版本原期限，較晚發布或日期相異本身不當作更正。
- [ ] 明確更正優先、版本內容其次、例行補充最後；不憑相似名稱強行合併。
- [ ] 重新整理保留項目身分與來源版本，差異能定位被修改的條件。
- [ ] 保留各來源區塊及共用條件依據，不憑模型重新拆分或合併活動。

- [ ] 經網站操作或實際輸出驗證上述交付行為；依已確認的整體入口，以保存來源、可替換模型回應及時間建立適用的可重複驗證。既有相關驗證仍通過。

## Scope and verification

本任務引用的故事與驗收條件可能由多張任務共同完成；本張負責範圍以上述交付行為及核取項目為準，不將其他任務尚未完成的功能當成本張完成證據。

完成時記錄使用的來源案例、實際操作／驗證結果及尚存限制。涉及真實模型呼叫時，記錄可取得用量；未知量明示未知。前置任務未完成時保持等待，不以 ready-for-agent 標記取代依賴檢查。

## Comments

網站測試使用公告 19129 的「三眼章魚直火燒烤」資料與模擬官方回應。只有日期不同的補充來源會保留待比對；冒用為更正會被拒絕；明示延期才更新參加期限，並顯示原日期和查證入口。測試延期沒有寫入正式資料。實際第二份官方公告的取得與人工比對仍待驗收。
