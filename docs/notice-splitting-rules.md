## 共用判斷順序

1. **擷取正文與順序。** 辨認活動時間、正文、注意事項容器，排除版本導覽。允許空白、全半形冒號，以及有結構佐證時的 x／× 差異用於比對頁首和正文標題。原文照存。日期、段落、表格、圖片、標題錨點都帶來源與順序。
2. **找區塊邊界。** 使用正文中的標題元素或整段短標題，結合粗體、字級、錨點、水平線及前後結構。括號、字級、水平線都是輔助訊號。段落中的按鈕名、表格欄名與句中括號留在原區塊。
3. **判斷層級和功能。** 標題下明列自己的一組日期與資格，可辨識為子活動，仍須核對條件是否真的適用該標題。有下層標題且承載共同內容的區塊可作分組。沒有獨立子活動、且正文有整體玩法及資格的頁面，可用公告標題建立一個活動，將玩法、進度獎勵、商店、效果及補充規則掛在下方。分類靠原文描述的行為與條件，字級只協助定位。
4. **條件依範圍套用。** 公告明示的期間、資格及注意事項可被所屬下層引用；子活動或方法明示的條件優先，額外前置條件按原文保留。日期按參加、分批開放、領獎、效果到期分開記錄。相同範圍且日期一致時，頁首完整時間可補正文簡寫；只知道日期就保留時刻未知。區塊只有日期或資格其中一項時，逐欄判斷繼承和來源。
5. **表格、圖片和附註沿用原位置。** 保留表頭、列欄合併與上下文。表後明指該表或該規則的例外仍屬於同一區塊。圖片跟隨可判定的正文位置；圖中獨有資訊或多件獎勵共用圖片時，個別內容與對應留待核對。
6. **局部待確認。** 只有歸屬、資格、期限等無法確定的段落進人工確認，保留原文及候選歸屬。已辨識的其他區塊可繼續處理；只有正文容器本身不明、或邊界無法可靠辨認時，才將整篇保留待拆。重跑時保留既有人工修正及活動連結。

## 實作驗收

- 六篇各自固定來源快照與預期拆分，核對表格、圖片位置、期間用途和例外條件。19129 應保持既有活動識別碼。
- 再選一篇未參與制定規則的新公告，檢查能否按結構拆分；同一快照另測公告編號改變，確認編號只用於來源識別。
- 加入局部歧義的測試，確認相鄰區塊仍可產出。用已有人工拆分的 19029 或 19030 副本驗證重跑後連結與修正都保留。
